Chapter 1: Fundamentals of Mobile Networks and End-to-End Architecture

Modern mobile networks are large distributed systems in which radio access, IP networking, transport infrastructure, core network functions, cloud platforms, and external data networks must operate as a single end-to-end service. Understanding how these domains interact is essential for network engineering, troubleshooting, performance analysis, deployment, and security.

This chapter establishes the architectural and networking foundation used throughout this book. The objective is not simply to describe the components of a mobile network, but to develop an end-to-end understanding of how a subscriber device establishes connectivity, how signaling and user traffic traverse the network, and how an engineer can isolate failures across multiple technological domains.

1.1 Introduction to Mobile Network Architecture

A mobile network can be understood as a distributed communication system connecting user equipment to services through several logical and physical domains. Although the technologies used by operators have changed considerably from 2G to 5G, the fundamental engineering problem remains similar: provide reliable connectivity between a subscriber and a destination while simultaneously handling authentication, mobility, addressing, policy, quality of service, charging, and security.

A simplified end-to-end path can be represented as: 

UE
  ```
  
  |
  | Radio Access
  v
  RAN
  |
  | Transport Network
  v
  Mobile Core
  |
  | IP / Data Network
  v
  Internet / Enterprise Network / IMS / Application
```

Each domain has different technologies, protocols, operational procedures, and failure modes. A radio problem may appear to the user as a complete loss of connectivity, while the actual cause may be located in the IP transport network, a core network function, a routing table, a GTP tunnel, a DNS service, or an external application.

For this reason, senior network engineers must avoid treating mobile connectivity as a single technology. Effective troubleshooting requires understanding the relationships between radio access, signaling, transport, routing, packet forwarding, and service delivery.

1.2 Evolution from 2G to 5G

Mobile networks have evolved through several generations, with each generation introducing new radio technologies, architectures, services, and packet-processing models.

1.2.1 2G

Second-generation systems introduced digital cellular communication at large scale. GSM became one of the most widely deployed 2G technologies. The architecture separated the radio access network from the core network, with dedicated functions for mobility management, authentication, subscriber databases, and circuit-switched services.

Packet-switched data was later introduced through GPRS and EDGE. This was an important architectural transition because mobile networks began transporting IP traffic in addition to traditional circuit-switched voice services.

From a networking perspective, the introduction of packet-switched data established concepts that would become increasingly important in later generations: tunneling, packet gateways, subscriber addressing, mobility management, and packet-based charging.

1.2.2 3G

Third-generation systems increased data capacity and introduced more sophisticated packet services. UMTS, based on the 3GPP architecture, separated radio access functions from the packet and circuit-switched core.

The evolution of 3G packet services continued the transition toward IP-based mobile connectivity. Packet gateways provided access to external packet networks while mobility management and subscriber databases continued to coordinate authentication and session establishment.

1.2.3 4G LTE

LTE represented a major architectural change. The radio access network became the Evolved Universal Terrestrial Radio Access Network (E-UTRAN), while the core evolved into the Evolved Packet Core (EPC).

LTE adopted an almost entirely packet-based architecture. The traditional circuit-switched architecture was no longer part of the LTE packet core. Voice services could instead be delivered through IMS and VoLTE.

The EPC introduced several functions that remain fundamental to mobile networking:

  • MME for control-plane mobility and session management.
  • SGW for user-plane mobility anchoring and packet forwarding.
  • PGW for connectivity toward external packet networks.
  • HSS for subscriber information and authentication-related data.
  • PCRF for policy and charging control.

LTE also standardized extensive use of IP transport and tunneling. GTP became a fundamental protocol for carrying subscriber traffic through the packet core, while SCTP became important for signaling transport between several network elements.

1.2.4 5G

5G introduced another major architectural evolution. The 5G Core (5GC) was designed around a Service-Based Architecture (SBA), allowing network functions to expose services to other network functions through standardized service interfaces.

Important 5G Core functions include:

  • AMF — Access and Mobility Management Function.
  • SMF — Session Management Function.
  • UPF — User Plane Function.
  • PCF — Policy Control Function.
  • UDM — Unified Data Management.
  • AUSF — Authentication Server Function.
  • NRF — Network Repository Function.
  • NSSF — Network Slice Selection Function.
  • NEF — Network Exposure Function.
  • UDR — Unified Data Repository.

5G also introduced a stronger separation between control-plane logic and user-plane packet forwarding, while enabling distributed deployment of network functions closer to subscribers and applications.

These changes make 5G significantly more software-oriented than previous generations. Network functions may be implemented as virtualized network functions or cloud-native network functions and deployed on general-purpose compute infrastructure.

1.3 The Major Domains of a Mobile Network

A practical mobile network can be divided into several domains. The exact physical implementation differs between operators, vendors, and deployment models, but the logical separation remains useful for engineering and troubleshooting.

1.3.1 User Equipment

User Equipment (UE) represents the subscriber's device. This may be a smartphone, modem, router, industrial device, vehicle, IoT device, or another cellular endpoint.

The UE participates in radio signaling with the RAN and establishes connectivity through the mobile core. From an IP perspective, the device eventually receives one or more IP addresses associated with its data connectivity.

1.3.2 Radio Access Network

The Radio Access Network (RAN) provides the radio interface between the UE and the operator's network.

In LTE, the primary radio access element is the eNodeB. In 5G NR, the corresponding radio access element is the gNodeB.

The RAN is responsible for radio-related functions such as scheduling, radio resource management, mobility procedures, and communication with the core network.

Although the RAN is often viewed primarily as a radio domain, it is also deeply connected to IP networking because traffic between RAN and core functions is transported through IP-based infrastructure.

1.3.3 Transport Network

The transport network provides connectivity between distributed network elements. It may include Ethernet, IP routing, optical transport, aggregation networks, routers, switches, and other infrastructure.

Transport networks are especially important because failures in this domain can affect multiple mobile services simultaneously.

Typical transport-network functions include:

  • Layer 2 connectivity.
  • Layer 3 routing.
  • Traffic engineering.
  • Redundancy and path protection.
  • Quality of Service.
  • Network synchronization.
  • Connectivity between geographically distributed sites.

1.3.4 Mobile Core

The mobile core provides centralized or distributed control and connectivity functions for subscribers.

The core is responsible for functions such as authentication, mobility management, session management, policy enforcement, packet forwarding, subscriber data, and connectivity to external networks.

1.3.5 External Networks

Mobile networks rarely terminate subscriber traffic internally. The subscriber may access the public Internet, enterprise networks, private applications, operator services, IMS, or other interconnected networks.

The boundary between the mobile core and external networks is therefore another important troubleshooting domain.

1.5 Control Plane and User Plane

One of the most important concepts in mobile network engineering is the distinction between the control plane and the user plane.

1.5.1 Control Plane

The control plane is responsible for signaling and decision-making. Control-plane procedures establish the state required for communication rather than carrying the subscriber's application payload itself.

Examples include:

  • Authentication.
  • Registration and attach procedures.
  • Mobility management.
  • Session establishment.
  • Bearer establishment.
  • Policy decisions.
  • Network-function discovery.
  • Subscriber authorization.

A control-plane failure can prevent a subscriber from obtaining service even when the physical and IP connectivity between network elements is completely operational.

1.5.2 User Plane

The user plane carries subscriber traffic. Examples include web browsing, video streaming, application traffic, voice media, VPN traffic, and other IP payloads.

In LTE and 5G, GTP-U is commonly used to encapsulate subscriber packets across the mobile transport network.

User-plane traffic can therefore continue to fail even when all control procedures have completed successfully. For example, a subscriber may successfully register and establish a PDU session while packets are dropped because of a routing error, incorrect GTP tunnel state, MTU problems, firewall policies, or an unavailable external network.

1.5.3 Why the Distinction Matters

A useful troubleshooting question is:

Is the failure preventing the network from establishing the required state, or is the established state unable to forward traffic?

The first situation usually indicates a control-plane problem. The second usually indicates a user-plane or data-path problem.

This distinction dramatically reduces the troubleshooting search space.

1.6 Layered Networking in Mobile Systems

Mobile networks use multiple protocol layers simultaneously. An engineer must understand both traditional networking layers and telecom-specific protocols.

A simplified stack for an IP-based mobile network can be represented as: 

Application
  |
  ```
  
  Transport
  |
  IP
  |
  Ethernet
  |
  Physical Network
```

Mobile networking adds additional protocol layers and tunneling mechanisms. For example, subscriber IP packets can be encapsulated in GTP-U and then transported using UDP over an IP network. 

Subscriber IP Packet
      |
      v
   GTP-U
      |
      v
     UDP
      |
      v
      IP
      |
      v
  Ethernet
  ```
```

This means that a packet capture may contain multiple logical layers that must be interpreted together.

A senior engineer should therefore be comfortable moving between packet layers rather than analyzing each protocol in isolation.

1.7 Ethernet and Layer 2 Fundamentals

Although mobile networks are commonly discussed in terms of 4G and 5G protocols, Ethernet remains one of the fundamental technologies underneath the IP transport infrastructure.

1.7.1 MAC Addresses

Ethernet uses MAC addresses to identify interfaces within a Layer 2 broadcast domain.

Switches use MAC address tables to determine where Ethernet frames should be forwarded. Incorrect or missing MAC learning can result in connectivity problems even when Layer 3 configuration appears correct.

1.7.2 VLANs

VLANs provide logical Layer 2 segmentation. Operators can use VLANs to separate different traffic categories or network functions.

Examples may include separate logical networks for:

  • Management traffic.
  • Control-plane traffic.
  • User-plane traffic.
  • Synchronization.
  • Operations and maintenance.

The exact segmentation model depends on the operator architecture. Incorrect VLAN configuration can cause failures that appear at higher layers as routing or application problems.

1.7.3 MTU

Maximum Transmission Unit (MTU) defines the largest IP packet that can normally be transmitted without fragmentation on a given Layer 3 interface.

Mobile networks frequently use encapsulation and tunneling. Every additional encapsulation header consumes part of the available packet size.

Consequently, MTU mismatches can produce subtle failures in which small packets work correctly while larger packets are lost.

This is particularly important when troubleshooting GTP tunnels, VPNs, IPv6 traffic, and cloud-native network environments.

1.8 IPv4 and IPv6 in Mobile Networks

1.8.1 IPv4

IPv4 remains widely deployed in mobile networks. Subscriber addresses may be assigned dynamically and may be private addresses translated through Carrier-Grade NAT before reaching the public Internet.

Network engineers must understand subnetting, routing, default gateways, address pools, and address translation when investigating subscriber connectivity.

1.8.2 IPv6

IPv6 provides a significantly larger address space and is increasingly relevant to mobile networks.

IPv6 introduces concepts such as Neighbor Discovery, Router Advertisements, IPv6 prefixes, and link-local addresses. Troubleshooting IPv6 therefore requires knowledge beyond traditional IPv4 ARP-based analysis.

1.8.3 Dual-Stack Deployments

Many environments support both IPv4 and IPv6. Dual-stack operation creates additional troubleshooting dimensions because an application may prefer one protocol family while the underlying network behaves differently for the other.

A useful troubleshooting approach is to explicitly determine:

  • Which address family the subscriber received.
  • Which address family the application is using.
  • Whether DNS returned IPv4 and IPv6 records.
  • Whether routing exists for the selected address family.
  • Whether security policies allow both protocols.

1.9 Transport Protocols: TCP, UDP and SCTP

1.9.1 TCP

Transmission Control Protocol provides reliable, connection-oriented transport. TCP uses sequencing, acknowledgements, retransmission, and congestion control.

TCP is widely used by applications and by several network-control technologies. In 5G Service-Based Architecture, HTTP/2-based communication operates over TCP.

1.9.2 UDP

User Datagram Protocol provides connectionless transport with minimal overhead. It does not itself provide reliable delivery, sequencing, or retransmission.

UDP is particularly important in mobile user-plane networking because GTP-U uses UDP as its transport protocol.

1.9.3 SCTP

Stream Control Transmission Protocol provides message-oriented transport with features designed for signaling applications.

SCTP is particularly important in 4G networks, where S1AP signaling between eNodeBs and MMEs is transported using SCTP over IP.

From a troubleshooting perspective, this means that a failure in SCTP association establishment can prevent higher-level mobile signaling from operating even though basic IP connectivity exists.

The engineer should therefore distinguish between: 

Physical connectivity
      |
  ```
  
  Ethernet connectivity
  |
  IP connectivity
  |
  SCTP association
  |
  Application signaling
```

1.10 DNS in Mobile Networks

Domain Name System (DNS) translates domain names into IP addresses and is essential to modern service delivery.

DNS can be involved in several different parts of a mobile environment. Subscriber traffic may require DNS resolution when applications access Internet services, while network functions themselves may rely on DNS or service discovery mechanisms depending on the deployment architecture.

A subscriber may therefore have a valid IP address and a working packet path while applications still fail because DNS resolution is unavailable.

When troubleshooting DNS-related problems, the engineer should separate name resolution from packet forwarding. 

Application
  |
  ```
  
  DNS Resolution
  |
  Destination IP
  |
  Routing
  |
  Packet Forwarding
```

If DNS resolution fails, testing the destination by IP address can help determine whether the underlying IP path is functional.

1.11 IP Routing Fundamentals

Routing determines how packets move between different IP networks. Mobile networks depend heavily on routing because RAN sites, core network functions, data centers, cloud platforms, and external networks are usually distributed across multiple IP subnets.

1.11.1 Routing Table

A router makes forwarding decisions based on its routing table. The destination IP address of a packet is compared against available prefixes, and the most specific matching route is normally selected.

A routing problem can therefore occur even when all interfaces are up. An interface being operational does not guarantee that the correct route exists toward the destination.

1.11.2 Static Routing

Static routes are manually configured and are useful in simple or controlled environments. They can also be used for specific traffic paths, default routes, or fallback scenarios.

However, static routing becomes difficult to manage at large scale because topology changes must be handled manually.

1.11.3 Dynamic Routing

Dynamic routing protocols allow routers to exchange reachability information and automatically adapt to topology changes.

Protocols such as OSPF, IS-IS, and BGP are widely used in service-provider and data-center environments. Their detailed operation is covered later in this book.

At this stage, the most important concept is that mobile traffic depends on the underlying IP network having valid and converged routes between network functions.

1.12 GTP and Mobile Traffic Tunneling

Mobile networks require a mechanism to maintain subscriber-specific traffic paths while the subscriber moves through the radio network and while the packet core remains distributed.

GPRS Tunneling Protocol (GTP) provides this capability in several mobile architectures.

1.12.1 GTP Control Plane

GTP-C is used for control-plane procedures associated with tunnels and subscriber sessions.

In LTE, GTP-C participates in procedures between EPC network functions. These procedures create and modify the state required for subscriber traffic forwarding.

1.12.2 GTP User Plane

GTP-U encapsulates subscriber IP packets inside GTP tunnels. 

Original Subscriber Packet
      |
      v
  ```
  
  +-------------------------+
  |        GTP-U            |
  +-------------------------+
  |          UDP            |
  +-------------------------+
  |           IP            |
  +-------------------------+
  |        Ethernet         |
  +-------------------------+
```

The outer IP addresses identify the transport endpoints, while the GTP tunnel identifies the logical subscriber traffic path.

This distinction is fundamental during packet analysis. An engineer may see a packet traveling between two core-network IP addresses while the actual payload belongs to a subscriber communicating with a completely different destination.

GTP-U analysis therefore requires understanding both the outer transport network and the encapsulated subscriber packet.

1.13 Mobile Network Interfaces

Mobile architectures define standardized logical interfaces between network functions. Understanding these interfaces allows an engineer to identify where signaling or traffic should be observed.

1.13.1 Important LTE Interfaces

  • S1-MME — control-plane signaling between eNodeB and MME.
  • S1-U — user-plane traffic between eNodeB and SGW.
  • S5/S8 — connectivity between SGW and PGW.
  • S11 — signaling between MME and SGW.
  • SGi — connectivity between PGW and external packet networks.
  • S6a — Diameter-based signaling between MME and HSS.

These interfaces provide a logical map for LTE troubleshooting. If an attach procedure fails, the engineer can determine which signaling interface should contain the relevant transaction.

1.13.2 Important 5G Interfaces

  • N1 — signaling between UE and AMF.
  • N2 — control-plane signaling between gNB and AMF.
  • N3 — user-plane traffic between gNB and UPF.
  • N4 — control interface between SMF and UPF.
  • N6 — connection between UPF and the external data network.
  • N11 — interface between AMF and SMF.

The 5G architecture also contains numerous service-based interfaces between network functions. These are discussed in detail in the chapters dedicated to 5G Core and Service-Based Architecture.

1.14 End-to-End Subscriber Connectivity

The most useful way to understand a mobile network is to follow a subscriber transaction from beginning to end.

Consider a subscriber attempting to access an Internet application. Several distinct stages are involved.

1.14.1 Radio Connectivity

The UE establishes radio connectivity with the serving cell. The RAN exchanges signaling with the core network to initiate registration, authentication, mobility management, and session procedures.

1.14.2 Authentication and Registration

The mobile core validates the subscriber identity and establishes the necessary security and mobility state.

A failure at this stage prevents the subscriber from reaching subsequent session-establishment procedures.

1.14.3 Session Establishment

The network establishes the resources required for user-plane connectivity. In LTE this involves bearer establishment. In 5G Standalone, the corresponding concept is the PDU Session.

1.14.4 IP Address Assignment

The subscriber receives an IP address or prefix according to the deployed architecture and requested connectivity.

1.14.5 User-Plane Establishment

The network establishes the user-plane path through the relevant packet forwarding functions.

In a simplified 5G path: 

UE
  ```
  
  |
  | Radio
  v
  gNB
  |
  | N3 / GTP-U
  v
  UPF
  |
  | N6
  v
  Data Network
  |
  v
  Internet / Application
```

1.14.6 Application Connectivity

Once the IP path is operational, the application can establish its own transport and application sessions.

At this point, the mobile network has successfully transformed a radio subscriber into an IP endpoint capable of communicating with external services.

1.15 Failure Domains

A major advantage of the end-to-end model is that it allows failures to be divided into logical domains.

1.15.1 Radio Failure

The UE may fail to establish or maintain radio connectivity because of coverage, interference, configuration, mobility, or radio-resource problems.

1.15.2 Transport Failure

The radio node may be operational while the IP transport path toward the core is unavailable.

Examples include:

  • Broken Ethernet connectivity.
  • Incorrect VLAN configuration.
  • Missing routes.
  • Routing protocol failure.
  • Packet loss.
  • MTU problems.
  • Interface errors.
  • Congestion.

1.15.3 Core Control-Plane Failure

IP connectivity between network functions may be completely operational while signaling fails because of incorrect configuration, unavailable network functions, authentication problems, protocol failures, or subscriber-data inconsistencies.

1.15.4 User-Plane Failure

The subscriber may successfully register and establish a session while user traffic fails.

Typical causes include:

  • Missing routes.
  • Incorrect GTP tunnel state.
  • Firewall rules.
  • Incorrect packet-forwarding configuration.
  • MTU issues.
  • UPF or gateway failures.
  • External network failures.
  • Asymmetric routing.

1.15.5 Application Failure

Finally, the mobile network may be functioning correctly while the destination application is unavailable or malfunctioning.

A senior engineer must therefore avoid automatically attributing every subscriber problem to the mobile network.

1.16 End-to-End Troubleshooting Methodology

Troubleshooting complex mobile networks requires a structured methodology. Randomly checking devices often increases investigation time because each engineer may examine a different layer without establishing a common failure boundary.

A practical methodology is:

  1. Define the exact symptom.
  2. Identify the affected subscribers, sites, or services.
  3. Determine whether the problem is isolated or systemic.
  4. Identify the last confirmed working point.
  5. Separate control-plane and user-plane behavior.
  6. Validate Layer 1 and Layer 2 connectivity.
  7. Validate IP addressing and routing.
  8. Validate transport-layer connectivity.
  9. Inspect the relevant telecom signaling.
  10. Inspect the user-plane packet path.
  11. Correlate logs, counters, alarms, and packet captures.
  12. Identify the smallest failure domain consistent with the evidence.

1.16.1 Start with the Symptom

"The network is down" is not a useful engineering symptom.

A better statement would be:

LTE subscribers at Site Group A can attach successfully but cannot reach external IPv4 destinations, while IPv6 connectivity remains operational.

The second description immediately reduces the investigation scope. It suggests that the radio and at least part of the control plane are operational and points toward an IPv4-specific user-plane or external network problem.

1.16.2 Determine the Scope

Scope is one of the strongest diagnostic signals.

If one subscriber is affected, subscriber-specific configuration may be relevant. If thousands of subscribers across multiple sites are affected, a shared infrastructure component becomes more likely.

Examples of useful scope questions include:

  • Is the problem affecting one UE or many UEs?
  • Is it limited to one cell?
  • Is it limited to one geographic region?
  • Is it limited to one APN or DNN?
  • Is it limited to IPv4 or IPv6?
  • Is it limited to one application?
  • Did the problem begin after a configuration change?

1.16.3 Find the Last Known Good Point

The most valuable troubleshooting question is often:

Where does the expected behavior stop?

For example: 

UE
  ```
  
  |
  | Registration: SUCCESS
  v
  AMF
  |
  | PDU Session: SUCCESS
  v
  SMF
  |
  | PFCP: SUCCESS
  v
  UPF
  |
  | User traffic: FAILURE
  v
  External Network
```

In this example, investigating radio registration would be inefficient because the evidence already demonstrates that registration is working.

1.17 Packet Capture and Protocol Analysis

Packet captures are among the most powerful sources of evidence available to a network engineer.

Tools such as Wireshark and TShark allow engineers to inspect packets at multiple protocol layers and correlate network behavior with signaling procedures.

1.17.1 Layer-by-Layer Analysis

A useful packet-analysis strategy is to move from lower layers toward the application rather than immediately searching for a specific message. 

Ethernet
  ```
  
  |
  IP
  |
  Transport
  |
  Telecom Protocol
  |
  Tunnel
  |
  Subscriber Packet
  |
  Application
```

For example, when analyzing GTP-U, the engineer should first confirm that the outer IP and UDP packets are present, then inspect the GTP tunnel information, and finally decode the encapsulated subscriber packet.

1.17.2 Capture Points Matter

A packet capture is meaningful only in the context of where it was collected.

A packet observed entering a network function does not prove that it was forwarded successfully out of that function.

Comparing captures at multiple points can therefore identify the precise location where packets disappear.

For example: 

Capture A              Capture B              Capture C
  ```
  
  gNB                    UPF                    External Router
  |                      |                      |
  | Packet present       | Packet present       | Packet absent
  |--------------------->|--------------------->|
```

This evidence strongly suggests that the failure occurs between the UPF and the external router, rather than between the UE and the UPF.

1.18 Logs, Counters, Alarms and Metrics

Packet captures provide detailed protocol evidence, but production troubleshooting rarely depends on packet captures alone.

A complete investigation typically correlates several observability sources.

  • System logs.
  • Protocol traces.
  • Interface counters.
  • Network alarms.
  • CPU and memory metrics.
  • Packet-loss statistics.
  • Latency measurements.
  • Session counters.
  • Throughput statistics.
  • Application logs.

The key principle is correlation. A single metric rarely identifies a root cause by itself.

For example, high packet loss combined with increasing interface errors and a corresponding increase in retransmissions provides much stronger evidence than packet loss alone.

1.19 Performance and Quality of Service

Functional connectivity is only one dimension of network quality. Production mobile networks must also satisfy performance requirements.

Important metrics include:

  • Latency.
  • Jitter.
  • Packet loss.
  • Throughput.
  • Connection setup time.
  • Session establishment success rate.
  • CPU utilization.
  • Memory utilization.
  • Interface utilization.
  • Packet-per-second capacity.

Quality of Service mechanisms allow networks to treat different traffic classes according to defined policies.

In mobile networks, QoS is closely associated with subscriber sessions, bearers, QoS flows, policy control, and packet forwarding. These concepts are developed in detail in later chapters.

1.20 Redundancy and High Availability

Carrier-grade networks cannot depend on individual network elements remaining operational indefinitely. Redundancy is therefore an architectural requirement.

Redundancy can exist at multiple levels:

  • Physical interface redundancy.
  • Link redundancy.
  • Router redundancy.
  • Network-function redundancy.
  • Data-center redundancy.
  • Geographic redundancy.
  • Cloud-platform redundancy.

A network engineer must understand not only the primary path but also how traffic is expected to behave when that path fails.

This introduces additional engineering concepts such as convergence, failover time, route withdrawal, state synchronization, load balancing, and session persistence.

1.21 Practical Troubleshooting Scenario

Consider a 5G Standalone deployment in which subscribers report that they can successfully register on the network but cannot access the Internet.

Observed Symptoms

  • UE detects the 5G cell.
  • Registration completes successfully.
  • Authentication succeeds.
  • PDU Session Establishment succeeds.
  • The UE receives an IP address.
  • Internet applications fail.

Initial Analysis

The evidence already eliminates several potential failure domains. Radio access is functioning sufficiently for registration. Authentication is functioning. The control plane has successfully established a PDU Session.

The investigation should therefore move toward the user plane.

Recommended Investigation

  1. Verify that the PDU Session is active in the SMF.
  2. Verify the corresponding PFCP state between SMF and UPF.
  3. Verify the expected GTP-U tunnel parameters.
  4. Capture traffic on the N3 interface.
  5. Confirm that subscriber packets reach the UPF.
  6. Inspect the N6 interface.
  7. Verify routing toward the external data network.
  8. Verify return routing toward the subscriber address pool.
  9. Check firewall and security policies.
  10. Check MTU and fragmentation behavior.
  11. Test connectivity using both packet capture and active probes.

Suppose the capture shows packets arriving at the UPF through N3 but no corresponding packets leaving N6. The investigation can now focus on the UPF forwarding behavior, routing, policy, or packet-processing configuration.

If packets leave the UPF but no response returns from the external network, the investigation moves toward routing, firewall policies, NAT, or the external network.

This illustrates a fundamental principle:

Troubleshooting should follow evidence across the packet path rather than assumptions about which technology is responsible.

1.22 The Network Engineer's Mental Model

A senior network engineer should maintain several simultaneous views of the network.

Architectural View

Understand which network functions exist, why they exist, and how they interact.

Protocol View

Understand which protocol should be present on each interface and what messages or packet types indicate normal operation.

Packet View

Understand how data is encapsulated and forwarded through the network.

Routing View

Understand how the network determines the next hop toward each destination.

Operational View

Understand alarms, logs, metrics, changes, deployments, failures, and recovery procedures.

Performance View

Understand whether the network is merely functioning or actually meeting its capacity, latency, availability, and QoS objectives.

The ability to move between these perspectives is one of the defining characteristics of senior-level network engineering.

1.23 Chapter Summary

Mobile networks are distributed systems that combine radio access, Ethernet, IP routing, transport protocols, telecom signaling, packet tunneling, cloud infrastructure, and external data networks.

The evolution from 2G to 4G and 5G progressively increased the role of packet networking and software-based network functions. LTE introduced the EPC and an extensively IP-based architecture, while 5G introduced the Service-Based Architecture and a more cloud-oriented approach to network functions.

The distinction between control plane and user plane is fundamental. Control-plane procedures establish the state required for communication, while the user plane carries subscriber traffic.

Ethernet, VLANs, IP addressing, routing, TCP, UDP, SCTP, DNS, and GTP form important parts of the networking foundation underneath mobile services.

Effective troubleshooting requires an end-to-end approach. Engineers should define the symptom, determine the scope, identify the last known good point, separate control-plane and user-plane behavior, validate lower-layer connectivity, inspect signaling and packet flows, and correlate packet captures with logs, counters, alarms, and metrics.

The following chapters build upon this foundation by examining IP networking in greater depth, followed by detailed 4G and 5G Core architectures, signaling, user-plane behavior, cloud-native infrastructure, security, observability, testing, deployment, and automation.

1.24 Key Concepts

  • Mobile networks consist of UE, RAN, transport, core, and external network domains.
  • LTE introduced the EPC as an IP-centric mobile core architecture.
  • 5G introduced the 5G Core and Service-Based Architecture.
  • Control-plane and user-plane functions must be analyzed separately.
  • Ethernet and IP networking provide fundamental transport capabilities for mobile networks.
  • TCP, UDP, and SCTP serve different transport requirements.
  • GTP provides essential tunneling capabilities in mobile networks.
  • Routing determines how packets reach distributed network functions and external networks.
  • DNS can affect service availability independently of basic IP connectivity.
  • Packet captures provide evidence of actual protocol behavior.
  • Logs, metrics, counters, and alarms complement packet-level analysis.
  • End-to-end troubleshooting should identify the smallest failure domain consistent with the available evidence.
  • Successful session establishment does not necessarily guarantee successful user-plane connectivity.

1.25 Engineering Checklist

When investigating a mobile connectivity problem, an engineer should be able to answer the following questions:

  1. What exactly is the observed symptom?
  2. How many subscribers or network elements are affected?
  3. Which geographical areas are affected?
  4. Is radio connectivity operational?
  5. Is control-plane signaling operational?
  6. Has the subscriber successfully authenticated?
  7. Has a session or bearer been established?
  8. Has an IP address or prefix been assigned?
  9. Is the user-plane tunnel operational?
  10. Does the expected route exist?
  11. Are packets arriving at the expected interface?
  12. Are packets leaving the expected interface?
  13. Is return traffic following a valid path?
  14. Could MTU, fragmentation, or packet loss be involved?
  15. Could a firewall or security policy be blocking the traffic?
  16. Did a recent configuration or network change precede the problem?
  17. Can the failure be reproduced and verified with packet captures or active tests?
