Chapter 6: 5G Core: SA and NSA Architecture

From LTE evolution to service-based 5G networking.

5G is not simply faster LTE. It changes the way the mobile core is designed, deployed, and operated.

The evolution from 4G LTE to 5G is often presented as a radio evolution. Higher frequencies, wider channels, massive MIMO, beamforming, and lower latency are certainly important parts of 5G.

But one of the most significant transformations happens somewhere else: inside the core network.

The 4G EPC introduced a highly distributed packet core built around network elements such as the MME, SGW, PGW, HSS, and PCRF.

The 5G Core introduces a different architectural philosophy. Instead of simply replacing one box with another, 3GPP defines a set of network functions that communicate through a service-based architecture.

This difference is fundamental.

The biggest change from EPC to 5GC is not the number of functions. It is the way those functions interact, scale, and evolve.

NSA and SA: Two Different Paths to 5G

The transition to 5G did not happen overnight.

Operators already had enormous investments in LTE radio networks, EPC infrastructure, transport, spectrum, and operational systems.

Replacing the entire mobile core before launching 5G would have been expensive and slow.

This created two major deployment models: Non-Standalone (NSA) and Standalone (SA).

5G Evolution ``` +-------------+ | 5G | +-------------+ | +---------+---------+ | | NSA SA | | LTE + 5G NR 5G NR | | EPC 5GC ```

The distinction is simple at a high level:

NSA uses the existing 4G core as an anchor.

SA uses the 5G Core directly.

But the engineering implications are much deeper than that simple definition.

5G NSA: Extending the LTE Architecture

In the most common NSA deployment model, the 4G EPC remains the control-plane anchor while a 5G NR cell is added to provide additional radio capacity and performance.

EPC +-----------+ | MME | +-----------+ | | +-----------+ | SGW | +-----------+ | +-----------+ | PGW | +-----------+ | | Internet ``` LTE + 5G Dual Connectivity +-----------+ | eNB | +-----------+ | | +-----------+ | gNB | +-----------+ | | UE ```

In NSA, the UE can use LTE and 5G NR together through a dual-connectivity architecture.

The LTE side provides the anchor while the NR side contributes additional radio resources.

This is why NSA is sometimes described as an evolutionary deployment. The operator can introduce 5G radio technology without immediately replacing the EPC.

NSA allowed operators to deploy 5G faster because they did not need to abandon the infrastructure that already carried millions of subscribers.

The EPC Anchor

The term anchor is important.

In an NSA architecture, the LTE/EPC domain retains important control and session-management responsibilities.

The exact architecture depends on the NSA option and deployment, but conceptually the relationship looks like:

UE | +----------------------+ | | LTE 5G NR | | eNB gNB | | +----------+-----------+ | EPC Anchor | v Core Network

The NR radio therefore does not automatically imply that the subscriber has moved to the 5G Core.

This is one of the most important concepts to understand when troubleshooting real networks.

A device displaying “5G” does not necessarily mean that the subscriber is using a 5G Core.

An NSA subscriber may be using 5G NR while the session remains anchored in EPC.

5G SA: A New Core

Standalone architecture changes the picture.

In SA, the 5G radio connects to a native 5G Core.

5G SA ``` UE | | gNB | | N2 / N3 | +---------+---------+ | | AMF UPF | | | | Control Plane User Plane | | +-----+-----+ | | | | | SMF AUSF UDM | | | +----------+---------------+ | DN Data Network ```

The architecture is now explicitly separated into control-plane and user-plane functions.

The AMF handles access and mobility.

The SMF manages sessions.

The UPF forwards user traffic.

Other functions provide authentication, subscriber data, policy, network discovery, and network selection.

This decomposition is one of the defining characteristics of 5GC.

From Network Elements to Network Functions

The EPC often feels like a collection of specialized nodes.

4G EPC MME ---- SGW ---- PGW | +---- HSS | +---- PCRF

The 5GC is more naturally understood as a collection of cooperating network functions.

5G Core AMF ---- SMF ---- UPF | | | +---- PCF | +---- AUSF ---- UDM | +---- NSSF | +---- NRF

This does not mean that every deployment consists of separate physical appliances.

A network function may run as software on virtualized or containerized infrastructure.

That makes the architecture much more flexible, but it also introduces a new operational reality.

In 5G, the network itself becomes software.

AMF — Access and Mobility Management Function

The AMF is one of the central control-plane functions in the 5G Core.

Its responsibilities include access and mobility management, registration management, connection management, and interaction with authentication procedures.

It is conceptually related to some of the responsibilities previously associated with the LTE MME, but it is not simply an MME with a new name.

The AMF participates in a service-based architecture and interacts with other 5GC functions using defined service interfaces.

UE | | N1 | AMF | +--------+--------+ | | | AUSF UDM SMF

The AMF is therefore a major control-plane coordination point.

The AMF does not carry the subscriber's application traffic. It manages the control state that allows the network to carry it.

SMF — Session Management Function

The SMF manages PDU sessions.

This includes responsibilities such as:

  • PDU session establishment
  • Session modification
  • Session release
  • UPF selection
  • IP address management
  • Traffic steering
  • Interaction with policy functions

The SMF can therefore be viewed as the function that controls how the user-plane session is built.

SMF | +--------+--------+ | | Policy UPF | | PCF N3/N6 | v Data Network

The SMF controls the session. The UPF forwards the packets.

Control decides where traffic should go. The user plane actually moves it.

UPF — User Plane Function

The UPF is the forwarding engine of the 5G Core.

It performs user-plane packet processing and forwarding.

This includes functions such as:

  • Packet forwarding
  • GTP-U termination and forwarding
  • Traffic detection
  • QoS enforcement
  • Traffic steering
  • Interaction with external data networks

The UPF can be deployed centrally or closer to users at the edge.

Central Core | UPF | Internet ``` Edge Location | UPF | MEC / Local DN ```

This is one of the architectural foundations for low-latency services.

Instead of forcing every packet through a distant centralized core, an operator can deploy UPFs closer to the application or subscriber.

Latency is not solved only by faster radio. Sometimes the biggest improvement comes from moving the user plane closer to the application.

UDM — Unified Data Management

The UDM provides subscriber-related data management functions in the 5G Core.

It is part of the architecture responsible for handling subscriber identity and subscription information.

The UDM works together with the AUSF and other functions during authentication and subscriber management procedures.

UE | v AMF | v AUSF | v UDM | Subscriber Data

The important architectural change is that subscriber information and service logic are more clearly decomposed into specialized functions.

AUSF — Authentication Server Function

The AUSF is responsible for authentication-related functions.

It works with the UDM and other network functions to support subscriber authentication.

UE | | Registration v AMF | | Authentication v AUSF | | Subscriber Data v UDM | v Authentication Result

This decomposition makes authentication an explicit service within the 5G Core architecture.

In a service-based core, authentication is no longer simply a procedure hidden inside one monolithic node. It becomes a network capability exposed through defined interactions.

PCF — Policy Control Function

The PCF provides policy control.

It is conceptually related to the policy role previously performed by the PCRF in EPC.

However, the 5G architecture expands the policy framework and integrates it into the service-based architecture.

Policy can influence:

  • QoS
  • Session behavior
  • Traffic treatment
  • Charging-related policy
  • Application-aware policy decisions
Application / Service | v PCF | v SMF | v UPF | v Traffic

The policy layer can therefore influence how a session is established and how its traffic is treated.

NRF — Network Repository Function

One of the most distinctive concepts in the service-based architecture is the NRF.

The Network Repository Function acts as a repository and discovery mechanism for network functions.

A network function can register its capabilities with the NRF. Other functions can use the NRF to discover available services.

NRF | +--------+--------+ | | | AMF SMF AUSF | | | +--------+--------+ | Service Discovery

This is very different from simply configuring every node with a static list of every other node.

Service discovery becomes an architectural capability.

In a cloud-native network, knowing where a service is can be as important as knowing what the service does.

NSSF — Network Slice Selection Function

The NSSF supports network slice selection.

Network slicing allows an operator to logically separate network resources and behavior for different services or customers.

Different slices can be associated with different requirements.

5G Core | +--------+--------+ | | | Slice A Slice B Slice C | | | eMBB IoT Critical ```

A simplified conceptual model might be:

  • Enhanced Mobile Broadband
  • Massive IoT
  • Low-latency or critical services

The exact implementation and deployment of slicing is more complex than assigning one slice to one application, but the architectural idea is important: the network can provide differentiated logical services over shared infrastructure.

Network slicing turns the mobile core from a one-size-fits-all transport system into a programmable service platform.

PDU Sessions

The 5G Core introduces the concept of a PDU Session.

A PDU session provides connectivity between the UE and a Data Network through the 5G Core.

UE | | PDU Session | gNB | | N3 | UPF | | N6 | Data Network

The PDU session is one of the most important concepts to understand when moving from EPC to 5GC.

In LTE, engineers are accustomed to thinking in terms of PDN connections, EPS bearers, and GTP tunnels.

In 5G, the terminology and state model evolve.

A PDU session can support different PDU session types, including:

  • IPv4
  • IPv6
  • IPv4v6
  • Ethernet
  • Unstructured

The session provides the logical connectivity context within which QoS flows are established.

QoS Flows and 5QI

One of the major changes from LTE to 5G is the move from the EPS bearer-centric QoS model toward a model centered on QoS Flows.

A PDU session can contain multiple QoS flows.

PDU Session | +----------+----------+ | | | QoS Flow QoS Flow QoS Flow | | | 5QI 9 5QI X 5QI Y | | | Internet Voice Critical App

The 5QI, or 5G QoS Identifier, provides a standardized way of characterizing QoS behavior.

Different traffic classes can therefore receive different treatment within the same PDU session.

This is particularly important for services where latency, packet delay, reliability, or priority matter.

A single subscriber session does not mean a single quality of service.

From EPS Bearers to QoS Flows

The conceptual transition can be visualized as:

4G PDN Connection | +---- Default Bearer | +---- Dedicated Bearer | QCI 5G PDU Session | +---- QoS Flow | +---- QoS Flow | +---- QoS Flow | 5QI

This does not mean that QoS became simple.

Quite the opposite.

The 5G architecture gives operators more flexibility to classify and control traffic.

5G does not merely increase bandwidth. It increases the number of ways the network can understand and treat traffic.

The Control Plane and User Plane in 5GC

The separation between control and user plane becomes especially clear in the 5G architecture.

CONTROL PLANE UE | v gNB | | N2 v AMF | +---- AUSF | +---- UDM | +---- SMF | +---- PCF | +---- NRF | +---- NSSF ``` USER PLANE ``` UE | v gNB | | N3 / GTP-U v UPF | | N6 v Data Network

This separation allows control-plane functions and user-plane resources to scale independently.

If subscriber signaling increases dramatically, the operator can scale control-plane functions.

If traffic volume increases, additional user-plane capacity can be deployed.

Control-plane scale and user-plane scale are different problems — and 5G treats them that way.

The Service-Based Architecture

The 5G Core uses a Service-Based Architecture, commonly abbreviated as SBA.

Instead of thinking only in terms of point-to-point interfaces between network elements, the architecture exposes services that authorized network functions can consume.

Service-Based Architecture ``` +---------+ | NRF | +---------+ | +--------------+--------------+ | | | AMF SMF AUSF | | | | | | UDM PCF NSSF | | Services ```

This architectural model aligns naturally with modern distributed software systems.

Network functions can be implemented as software components, scaled dynamically, and deployed across distributed infrastructure.

But this flexibility introduces additional dependencies.

A failure is no longer necessarily:

“Node X is down.”

It may instead be:

“Function X is running, but it cannot discover function Y, authenticate to it, resolve its service endpoint, or reach the required backend service.”
Cloud-native networking replaces some hardware failures with software, orchestration, discovery, and dependency failures.

NSA Versus SA: Engineering Perspective

The difference between NSA and SA can be summarized technically:

NSA SA ``` LTE + 5G NR 5G NR | | EPC Anchor 5GC | | MME / SGW / PGW AMF / SMF / UPF | | EPC Model SBA Model ```

NSA is primarily an evolutionary deployment.

SA is a new architectural foundation.

NSA can accelerate 5G radio deployment while leveraging existing EPC infrastructure.

SA enables capabilities that depend much more naturally on the 5G Core, including:

  • Native 5G service-based architecture
  • Advanced QoS flows
  • Network slicing
  • Flexible UPF placement
  • Edge computing integration
  • Cloud-native network functions

This does not mean NSA is obsolete or technically useless.

It reflects a different point in the operator's migration strategy.

A Practical Subscriber View

Consider a subscriber connecting to a 5G SA network.

The simplified sequence is:

UE | | Registration v gNB | | N2 v AMF | +---- Authentication ----> AUSF | | | v | UDM | +---- Session Request ---> SMF | +---- Policy ---> PCF | +---- UPF Selection | v UPF | | N3 | gNB | v UE

Once the session is established, user traffic can flow through the selected UPF.

The control plane establishes the rules. The user plane executes them.

The control plane creates the path. The user plane becomes the path.

Where Troubleshooting Changes in 5G

The troubleshooting methodology learned in the EPC remains valuable.

But the number of dependencies increases.

In EPC, an engineer might investigate:

UE | eNodeB | MME | SGW | PGW | Internet

In 5GC, the same investigation may involve:

UE | gNB | AMF | SMF | AUSF | UDM | PCF | NRF | UPF | Data Network

Not every procedure traverses every function.

That distinction is important.

The engineer must understand which service is required for the specific procedure being investigated.

In 5G, troubleshooting means following dependencies as much as following packets.

The New Failure Domains

A 5G Core failure can occur at several layers.

5G Failure Domains ``` | +--------------+--------------+ | | | Radio Control User Plane | | | gNB AMF / SMF UPF / N3 | +----------+----------+ | | | SBA Database Policy | | | NRF UDM PCF ```

This creates a much larger troubleshooting matrix.

For example:

  • Registration can fail because of radio or AMF issues.
  • Authentication can fail because of AUSF or UDM interactions.
  • PDU session establishment can fail because of SMF, policy, or UPF selection.
  • User traffic can fail even when registration and session establishment succeed.
  • Service discovery problems can prevent otherwise healthy network functions from communicating.
  • Policy problems can create traffic behavior that looks like a forwarding failure.
A green dashboard does not prove that the service works. Distributed systems can be locally healthy and globally broken.

5G Is an Evolution of Concepts, Not the End of Them

Despite all the new terminology, many engineering principles remain familiar.

There is still a subscriber.

There is still authentication.

There is still session state.

There is still a control plane.

There is still a user plane.

There are still tunnels.

There are still IP addresses.

There are still routing decisions.

There are still packets that can disappear.

The architecture has changed, but the fundamental engineering problem has not: understand the expected behavior, observe what actually happened, and locate the divergence.

New architecture does not eliminate old engineering principles. It gives them more layers to operate across.

Chapter Takeaways

5G NSA and SA represent two distinct architectural approaches to deploying 5G.

NSA extends LTE using 5G NR while retaining the EPC as the anchor in common deployments.

SA connects 5G NR directly to the native 5G Core.

The 5GC is based on a service-based architecture built from specialized network functions.

The AMF handles access and mobility management.

The SMF manages PDU sessions and controls the user-plane path.

The UPF forwards user traffic and can be deployed close to the edge.

The UDM provides subscriber data management functions.

The AUSF handles authentication-related functions.

The PCF provides policy control.

The NRF enables network-function registration and service discovery.

The NSSF supports network slice selection.

A PDU Session provides UE connectivity to a Data Network through the 5G Core.

A PDU session can contain multiple QoS Flows, each associated with QoS treatment characterized using identifiers such as 5QI.

The most important conceptual transition is this:

4G EPC | Network Elements | Bearer Model | Point-to-Point | v 5G 5GC | Network Functions | Service-Based Model | PDU Session / QoS | v Cloud-Native Core
5G Core is not simply a collection of new network elements. It is a new way of building the mobile network as a distributed software platform.

And that architectural change prepares the ground for everything that follows: cloud-native deployment, Kubernetes, containers, service discovery, observability, distributed user planes, edge computing, automation, and eventually the operational challenges of running telecom infrastructure as software.

The radio may connect the device to 5G. The core determines what that 5G network can actually become.

The next step is therefore not simply learning more 5G interfaces. It is understanding what happens when the 5G Core itself becomes cloud-native.

That is where telecom engineering meets Kubernetes, containers, networking plugins, DPDK, SR-IOV, CPU pinning, NUMA awareness, observability, and the realities of running a distributed mobile core on modern infrastructure.

The future of the mobile core is not only faster networking. It is programmable networking.
